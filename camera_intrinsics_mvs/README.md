# 海康机器人 GigE 相机标定

这套脚本使用随项目提供的 MVS 5.0.1 SDK 读取 GigE 相机，并用普通棋盘格估计 OpenCV 透视模型的 5 个畸变系数。每台相机和镜头组合单独采集、单独求参。当前机器上 SDK 已放在 `~/.local/opt/MVS-5.0.1`，无须修改系统驱动；`run.sh` 选择本机带 GTK 的 OpenCV 4.5.4。

## 图形上位机：保存、求参、实时位姿

```bash
./run.sh gui --serial DB2189859
```

也可加 `--output-dir /path/to/camera_images` 和 `--intrinsics /path/to/intrinsics.json` 指定初始路径。窗口可刷新并切换相机，选择图片文件夹，调节手动增益，点击“保存图片 + JSON”或按空格取帧。保存的是原始分辨率 PNG；同名 JSON 记录相机型号、序列号、帧号、曝光、增益等信息。每台物理相机使用独立文件夹，程序会拒绝在其他相机的文件夹继续保存或用混合相机的图片求参。

物理位置固定绑定：`cam1 = DB2189859`，`cam2 = DB2189878`。选择一个保存根目录后，普通内参照片会自动进入 `cam1_parm_inside_DB2189859/` 或 `cam2_parm_inside_DB2189878/`；外参配对照片进入 `cam1_parm_outside_DB2189859/` 或 `cam2_parm_outside_DB2189878/`。若选择的已是上述任一相机目录，程序使用它的父目录作为保存根目录。内参结果 `calibration_时间戳/intrinsics.json` 位于对应的 `inside` 目录中。换相机或调换物理位置时，应先更新 `mvs_gui.py` 中的 `CAMERA_POSITIONS` 绑定。

棋盘格为 **10×7 方格、9×6 内角点**。用尺量好实际单格尺寸，填入“棋盘格距 (mm)”。至少拍 15 张有效照片，建议 25～35 张不同位置、距离和倾角的照片。点击“一键生成内参”后，窗口下方显示计算日志，结果位于所选图片文件夹中的 `calibration_年月日_时分秒/`，其中含 `intrinsics.json`、`camera_info.yaml`、逐张角点可视化。计算采用 `findChessboardCornersSB` 与 `calibrateCameraExtended`，固定 `k3=0`；标定完成会自动载入结果。

点击“查找已有内参”或“浏览内参文件…”可切换到该相机已有内参；程序核对型号、序列号、图像尺寸及 9×6 棋盘规格。打开“实时位姿”后，棋盘完整入镜时显示角点与坐标轴，并报告棋盘中心在相机坐标系的 X/Y/Z、光心到棋盘中心的距离和重投影 RMS。关闭开关可继续普通预览。标定和位姿的毫米值都按输入的**实测格距**计算；曝光、增益不会改变几何内参，但对焦、镜头、分辨率、ROI 或装配改变后需重新验证。图形程序使用 `PyQt5`，若新机器缺少该包，需安装系统包 `python3-pyqt5`。

增益也可在滑条右侧的“输入”框直接填写；按回车或点“应用增益”提交。右侧以四位小数显示相机实际回读值，设备若按离散档位设置增益，输入值与回读值可能略有差异。连接相机后，上位机会自动查找匹配内参。点“查找已有内参”可以看到带型号、序列号、分辨率和 RMS 的候选列表。当前 `DB2189859` 的推荐内参为 `/home/ybbb/桌面/相机内参标定/DB2189859/calibration_recommended_20260917/intrinsics.json`；要手动选文件，请选名为 **`intrinsics.json`** 的文件，而不是每张照片旁的 `frame_XXXX.json`。

## 双相机棋盘格外参

先分别给两台相机完成内参标定。手动逐台采集时，为相机 1、相机 2 各选一个单独图片文件夹。勾选“外参配对采集”并设置组号 1，将棋盘固定不动，分别从两台相机保存一张完整棋盘照片；同组号写入两张照片各自的 JSON。只有一台相机连接时，配对照片也进入该相机专属的 `camX_parm_outside_序列号/` 目录，原有内参照片不会被覆盖或混入；旧版本保存在根目录、带 `pair_id` 的照片也会被内参算法跳过。**两台相机拍完同一组之前，不得移动棋盘。**随后点击“下一组”，移动棋盘并停稳，再各拍一张。组与组之间棋盘可以移动，不需要始终处于同一世界位置。建议 10～20 组，包含不同距离和左右、上下倾角。可以开两个上位机窗口各连接一台相机；若逐台切换连接，拍同一组时棋盘必须始终保持不动。每张照片都需要检出完整 9×6 内角点。手持或运动中的棋盘应改为双相机硬件同步触发；仅给照片填写相同组号无法保证物理位姿相同。

若两台不同序列号的相机都能在同一网段打开，连接相机后勾选“外参配对采集”会自动打开另一台并左右并排预览；取消勾选或只检测到一台时保持原来的单画面。双画面模式把**两台**相机临时限制到 6 fps，并设置约 50 µs 的 GigE 包间隔，以降低共用千兆网口时的丢包；退出该模式时恢复原帧率和包间隔。画面下方分别显示完整帧、丢包和未取到帧的计数。右侧有第二台相机的增益输入框。

本机第二台 `DB2189878` 当前通过 MVS Force IP 暂时设为 `192.168.1.214/24`，第一台 `DB2189859` 是 `192.168.1.213/24`，网卡是 `192.168.1.88/24`。如果第二台重启后回到 `169.254.*`，需在 MVS 的 **Tool → IP Configurator** 将它配置到与网卡相同的 `192.168.1.*` 网段，且两台相机 IP 不得重复。

双画面模式下按空格或点击“保存图片 + JSON”会在同一组号下各保存一张原始分辨率照片，分别进入保存根目录下对应的 `cam1_parm_outside_DB2189859/` 和 `cam2_parm_outside_DB2189878/`。程序先检查两幅画面都新鲜、完整且检出棋盘，再一起保存；失败时清理本次已写入的文件。外参窗口的“填入当前相机”按固定物理位置填入目录和匹配的内参文件，不受主界面左右显示顺序影响。此采集方式使用软件读取的最近帧，**不保证严格同步曝光**；棋盘必须在一组两张照片拍摄期间保持不动。

点击“双相机棋盘格外参…”，填入两台相机的文件夹和各自的 `intrinsics.json`。可在连接相机时点“填入当前相机”。输入**实测**方格边长、预期夹角后计算；至少 5 组有效配对。算法按组号配对，固定两台相机内参，用 OpenCV `stereoCalibrate(CALIB_FIX_INTRINSIC)` 求相机 1 到相机 2 的旋转和平移，并检查每组位姿；不会把两台相机独立拍摄的内参照片自动配对。结果保存在相机 1 图片目录的 `stereo_时间戳/extrinsics.json`，旁边的 `detected_corners/` 用于核对角点。若双目 RMS 超过 1 px，或逐组相对位姿偏差过大，程序只写 `pair_review.json`，**不生成可用的 `extrinsics.json`**；请检查对应组号并重拍。几何检查只能发现明显冲突，不能从照片证明棋盘在同组两次曝光间绝对未移动。两台相机可使用不同分辨率，但各自照片须与各自内参匹配。相机装配、对焦或棋盘实测尺寸错误会影响外参质量。

结果中的 `R_camera1_to_camera2` 和 `T_camera1_to_camera2_mm` 满足 `p2 = R·p1 + T`；`camera2_center_in_camera1_mm` 是相机 2 光心在相机 1 坐标系中的位置。60° 只用于结果核查，不强制约束计算。也可在终端使用 `./run.sh stereo --camera1-images A目录 --camera2-images B目录 --intrinsics1 A内参 --intrinsics2 B内参 --square-mm 50 --output 新结果目录`。

## 1. 接线、试读

给相机供电，使用网线连接到本机以太网口，再执行：

```bash
cd /home/ybbb/codex_prj/camera_intrinsics_mvs
./run.sh probe
```

`probe` 会列出型号、序列号和 IP。若显示 `No GigE camera found`，先看 `ip -br link` 中以太网口是否为 `LOWER_UP`，检查供电、网线和相机 IP。若能枚举但无法打开，再检查相机和网口是否在同一子网；不要把系统自带笔记本摄像头 `/dev/video0` 当作这台 GigE 工业相机。相机实际最大分辨率见海康官网产品页，采集时以相机当前 `Width`、`Height`、ROI 为准。

先保存一张诊断帧，无须打开预览窗口：

```bash
./run.sh snapshot --serial 相机序列号 --output /home/ybbb/桌面/相机内参标定/diagnostic.png
```

同名 JSON 会记录设备型号、序列号、相机参数、像素格式、丢包数和图像亮度。若枚举列表重复出现同一序列号，脚本会优先选择与相机同子网的主机 IP。`snapshot` 可诊断任何已枚举的 GigE 相机；正式 `capture` 默认只接受项目指定的 `MV-CS050-10GC`。若要明确标定其他型号，必须传入 `--expected-model` 并用另一目录保存。

实时预览可用 `./run.sh preview --serial 相机序列号 --output-dir /home/ybbb/桌面/相机内参标定/preview_相机序列号` 启动。窗口内的 `Gain x0.1` 滑条会直接调节相机手动增益，并显示实际回读值；预览按窗口尺寸缩放，保存仍为原始分辨率。点击预览窗口后，按空格保存 PNG，按 `q` 或 `Esc` 退出；保存的图像不会含预览文字。同名 JSON 记录保存时的相机参数。预览可用于任何已枚举相机，保存的照片不自动作为棋盘标定样本。

## 2. 准备棋盘格并拍照

使用 `/home/ybbb/桌面/相机内参标定/checkerboard_50mm_10x7_600x450mm.pdf`，以 **100% 实际尺寸**打印。图案为 10×7 方格、9×6 内角点。贴在平整硬板上，测量单格节距并记录实测值。`--square-mm` 以后应填实测值。

保持镜头最终使用的焦距、对焦、光圈和相机的分辨率、ROI、binning 不变。避免过曝、运动模糊和高反光。先让整块棋盘清晰入镜，建议获取 25～35 张不同姿态的照片：中央、四角、边缘；正对、左右倾斜、上下倾斜；近、中、远距离。棋盘尽量覆盖较大画面，但所有 54 个内角点需可见。两次按空格之间移动板并停稳；避免连拍几乎相同的姿态。可先用少量照片试拍检测。

```bash
./run.sh capture --serial 相机序列号 --output /home/ybbb/桌面/相机内参标定/相机序列号/images --max-images 35
```

预览窗口中空格保存，`q` 或 `Esc` 结束。只有棋盘成功检出且该帧未丢包时保存无损 PNG。采集目录同时保存 `capture_manifest.json`，含序列号、相机设置、帧号、像素格式和图像转换方式。多台相机务必指定 `--serial` 并使用不同目录。

## 3. 求参和验证

建议另拍 5～10 张新姿态图，放在独立的 `validation_images` 目录中；目录中只放图像。求参：

```bash
./run.sh calibrate \
  --images /home/ybbb/桌面/相机内参标定/相机序列号/images \
  --validation-images /home/ybbb/桌面/相机内参标定/相机序列号/validation_images \
  --square-mm 50 \
  --output /home/ybbb/桌面/相机内参标定/相机序列号/result
```

`--validation-images` 可暂时省略。结果含 `intrinsics.json`、ROS `camera_info.yaml`、`detected_corners/` 可视化。JSON 给出像素单位 `K`、顺序为 `k1,k2,p1,p2,k3` 的 `D`、整体及逐图重投影误差、覆盖范围和警告；验证图仅用于单张位姿拟合与重投影核查，不参与内参拟合。重投影误差只是内部几何一致性指标，还要检查去畸变后的直线和独立场景。固定对焦、ROI、binning 或镜头装配改变后应重新验证或重标定。

算法：OpenCV `findChessboardCornersSB` 检测亚像素角点；`calibrateCameraExtended` 用 5 系数针孔/径向/切向模型全局最小化重投影误差。该 8 mm 定焦镜头不按鱼眼模型预设。至少需要 15 张有效图，推荐 25～35 张且覆盖充分；脚本不自动删高误差图，需检查可视化后决定是否重拍。
